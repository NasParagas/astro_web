## CPU がプログラムを実行する手順

### 前提(CPUはメモリの値をどうやって取得している？)

CPUが addr の32本の線の電圧を、目的のアドレスを表すパターンに変える
メモリ内部の回路がその電圧パターンを受けて、対応する記憶素子を選ぶ（アドレスデコーダ）
選ばれた素子の中身が rdata の32本の線に電圧として現れる

### 手順

広く見ると

- (C や Rust などで書かれたソースコードがあり、それを CPU で採用されている ISA を target としてコンパイルされた machine code がある)
- 実行する machine code をメモリに展開する
- CPU がメモリから machine code を読み込む
- その machine code をもとに計算処理を行う

細かく見ると

- (展開までは同じ)
- CPU がメモリに対して、展開された machine code の始まりであるアドレスを渡し、そこの値を取得する(フェッチ)
- もらった値(命令)の bit 列がどのような意味を持つのかを判定する(デコード)
- デコードした命令の内容に応じて、計算やメモリ・レジスタへの読み書きを行う
  - 命令の中身で、読み書きや計算の対象とするものは次のいずれかで指定される
    - レジスタの番号
      - レジスタ = CPU内に存在する計算データ用の記憶領域。命令の中に含まれる
    - 即値
      - 命令の bit 列から生成される数値
  - どちらを使うかは命令によって異なる
- 今現在実行している命令のアドレスを格納している、プログラムカウンタ(PC)が更新され、その値をメモリに渡し、命令をフェッチする
  - たとえば、命令セット RV32I は命令が 32bit 固定のため、PC は 4 (32/8=4byte) 増やせば良い。ジャンプ命令の場合はジャンプ先、分岐命令の場合は分岐先のアドレスが設定される
